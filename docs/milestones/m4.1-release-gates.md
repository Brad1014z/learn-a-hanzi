# M4.1 — First Ten Minutes release gates

**Status: engineering implementation present; pilot and distribution blocked.**

The milestone serves English-speaking complete beginners ages 12–16 on offline-first
Android (API 26+). The core quest is **Shape Shift: 人 → 大 → 天**. Social/cloud and iOS
remain out of scope until every gate below passes.

## Implemented engineering gates

- A lifecycle `QuestController` owns immutable UI state and explicit actions.
- `QuestStore` commits review log, SRS state, XP/week metadata, rank transition result,
  and sync outbox in one Room transaction. Card and chest IDs are idempotent.
- Session state cannot advance while a commit is pending; failures retain the completed
  card and expose a safe retry.
- Reset clears progress, logs, XP/week/quest/sync metadata and pending outbox records,
  then writes a restore barrier so a stale cloud snapshot cannot reappear.
- Daily planning keeps all due reviews, admits at most three core new characters, and
  offers at most two optional new characters after the core chest. Five is absolute.
- Collection contains encountered characters; Browse exposes the curriculum with search;
  navigation is Browse/Collection → Detail → Practice.
- Learner UI no longer shows internal grades or grader subscores. Feedback uses location,
  length, direction, text, subtle accept haptics, reduced-motion rejection, and semantics.
- `SOCIAL_ENABLED=false` removes Family/sign-in/sync/boards from pilot and release flow.
- Debug builds contain a consent-gated local JSONL stroke exporter. Release builds compile
  a no-op stub and contain no file-writing exporter implementation.
- Ingest has a hard-fail `LessonContent` validator for ordering, readings, tones, target
  occurrence, learned-character vocabulary, audio, uniqueness, and teacher metadata.

## How the content gate is enforced

The teacher-content gate is not a promise in a document — it is enforced in three places,
so an unreviewed build cannot quietly reach a learner:

1. **Signing time.** `verifyPilotContent` (app/build.gradle.kts) runs before
   `packageRelease` *whenever release signing is configured*, and fails the build while
   `content/lesson-content-first30.json` approves zero lessons. Unsigned release builds
   skip it on purpose, so PR CI keeps exercising R8 and the keep rules. CI therefore only
   signs on `v*` tags — tagging is the moment of truth.
2. **Runtime, at the point of offer.** `RoomContentRepository.worlds()` filters the
   curriculum to characters with signed lessons in release builds, so the Collection,
   Browse shelf and quest can only ever contain approved characters. Debug builds keep
   the engineering-draft fallback so development never waits on review.
3. **Runtime, as a backstop.** The `check` in `lessonContentFor` still refuses to
   fabricate content in a release build, now as an internal-error guard rather than
   something a learner can trip.

*Why this changed (2026-09-05): the gate originally lived only in step 3. Because a
release build still offered all ~181 dataset characters — the Browse shelf shows every
one — opening any character threw `IllegalStateException` and killed the app. A signed
pilot APK would have installed and then crashed on the first tap. Verified with a
release-variant test before the fix: `人 has no signed LessonContent`. `ContentGateTest`
now locks in the corrected behaviour in both variants.*

## Social blockers before re-enable

1. `friends` collapses incoming and outgoing pending edges to one Boolean. `FamilyScreen`
   can therefore offer confirmation to the requester, while Firestore rules permit only
   the non-requesting party to update `confirmedAt`. Model requester/recipient state
   explicitly and test both clients against the rules.
2. `friendCodes/{code}` update rules check only the *new* `uid`; another signed-in user can
   attempt to rewrite an existing code to themselves. Enforce existing-resource ownership,
   profile/code consistency, rotation atomicity, and emulator rule tests.
